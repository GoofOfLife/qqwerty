#about
КАК ЧИТАТЬ | Каждый раздел словаря (#tracks, #fx, #chains, #hrInstances, #hrPoints, #earlyFinal, #attempts, #vehiclesEstimate, #loss_reasons, #events, #eventDetails, #funnel, #frames, #blobs, #trackFrames, #detector, #rejectedCandidates, #setup, #pointAttribution, #values) соответствует таблице выгрузки с тем же именем. В CSV поля fx выгружаются с префиксом fx_ (колонка fx_chi — поле chi раздела #fx).
ЕДИНИЦЫ | Время t, t0, t1, tEnd, tShow, tEarly, tSplit… — секунды ВИДЕО-времени (метка кадра), не стенные часы. Поля trel, tEarlyRel, tRel — секунды от начала трека (или от начала разбираемой попытки). Скорости — км/ч; пути, невязки, sg, rms — метры; x, y, w, h, area — пиксели кадра анализа (размер aw×ah в #setup, при калибровке — масштаб px→м своё в каждой полосе); доли и оценки гипотез — 0…1; флаги — 0/1; пусто/null — значение не определено или не применимо.
НАДЁЖНОСТЬ | ИЗМЕРЕНО: счётчики, времена, координаты, невязки, скорости, значения полей CORE. ГИПОТЕЗА: hrCause*, hrScore*, efClass*, efScore*, efExplain, evidence, against, explanation, stageLost/notShownWhy (по состоянию на конец трека), оценка машин vehStrict/vehLinked. Гипотеза назначается только при двух и более независимых признаках; все оценки по каждой причине (sc_*) выгружены — классификацию можно пересчитать иначе, пороги — в meta.xcfg.
ЧТО НЕ СМЕШИВАТЬ | Цепочка детектора (chains) — последовательность рамок детектора машин в одной полосе; трек (tracks) — объект трекера; оценка машин (vehiclesEstimate) — компонента графа «цепочки ↔ треки»; попытка (attempts) — один вызов итоговой оценки по отрезку трека (у трека может быть несколько); ранняя попытка — один вызов Tracker._early. Числа этих сущностей НЕ складываются: число уникальных машин неизвестно.
ЛИМИТЫ | Журналы ограничены (meta.tables: rows/cap/dropped, meta.drops). Всё, что не поместилось, посчитано (dropped, drops.*) — выгрузка не теряет записи молча. События одного типа на один трек ограничены (xcfg.evPerType), их полный счёт — поле evCounts строки трека.
НЕ ИМИТИРУЕТСЯ | Если значение нельзя получить без изменения алгоритма, поле пустое (null), а не подставленное. Список таких полей и ограничений — meta.limitations и summaryText.
#tracks
id | Номер трека (сквозной в прогоне). Один объект трекера; одна машина может дать несколько треков (фрагментация, смена ID), один трек — склеить несколько машин.
res | Итог трека: PASS — есть скорость (итоговая T1 или предварительная T2, см. finalTier); ALIVE — трек ещё жив на момент выгрузки; иначе код отказа CORE (tr.rej: REJECT_*), либо ENDED (число показывалось, итога нет), либо NEVER_SHOWN.
cause | Нормализованная причина: PASS, ALIVE, DUPLICATE (убит как дубль), GAP_RESET (сброс по паузе), FLUSH_VIDEO_END / FLUSH_STAB_LOST / FLUSH_BG_RESET / FLUSH_OTHER (принудительное завершение), NO_CONFIRM_FRAMES (не набрал кадров подтверждения), NO_MOVE (не двигался), либо код отказа CORE без REJECT_ с подпричиной (HIGH_RMS:FAR_SCALE, TOO_FEW_POINTS, NO_CONFIRM и т.д.).
endBy | Как закончился трек (tr.why CORE): miss — потерян и истёк limbo; occluded — потерян за преградой; gap — сброс по паузе; flush — принудительное завершение; dup — убит как дубль; пусто — иное.
endWhy | Причина завершения, переданная в событие end (аргумент why колбэка трекера).
rej | Код отказа CORE (tr.rej): REJECT_DUPLICATE, REJECT_TOO_FEW_POINTS, REJECT_NO_FIT, REJECT_TOO_SLOW, REJECT_HIGH_RMS / REJECT_HIGH_REL_ERR / REJECT_RMS_AND_REL, REJECT_NO_CONFIRM, REJECT_SPEED_SPREAD, REJECT_TOO_SHORT_PATH, REJECT_UNVERIFIED. Пусто, если отказа нет. Может быть непустым и при res=PASS (когда выдан предварительный результат вместо итога).
flags | Описательные флаги состояния трека через | (NOT_CONFIRMED, NOT_MOVED, PTS<finalMin, PTS<showMin, WIN<minShow, PATH<minTravel, REL>showErr, RMS>finalMax, SPEED<min, SPEED>max, SPREAD, ENDED_BY_MISS/OCCLUDED, LANE_SWITCH, XLANE_BLOCKED, FRAG_SUPPRESSED, BLOB_MERGED, STAB_NOT_OK, AREA_JUMP, SPEED_JUMP, NO_DET_AT_LOSS, DET_AT_LOSS). Это наблюдения, а не причины: причину назначает cause/hrCause.
cls | Класс трека по рамкам детектора (сумма score по классам привязанных блобов): car, truck, bus, другие классы детектора; unknown — детектор ни разу не подтвердил блоб трека.
clsScore | Максимальный score детектора среди рамок, подтвердивших блобы трека.
detFrac | Доля блобов трека, подтверждённых рамкой детектора (перекрытие ≥ 0.3).
large | 1 — класс truck или bus.
dv | Номера цепочек детектора (chains.dv), с которыми пересекались блобы трека, через +.
lane0 | Полоса при рождении трека.
lane | Полоса на момент конца трека.
laneSw | Сколько раз трек менял полосу (CORE).
xBlocked | Сколько раз блоб соседней полосы был отвергнут привязкой (XLANE_BLOCKED).
dupOf | id трека-«победителя», если этот трек убит как дубль; иначе пусто.
idSwitch | 1 — CORE зафиксировал при рождении этого трека смену ID (трек продолжает недавно потерянный; связь replaces/replacedBy).
t0 | Время рождения трека, с.
tEnd | Время завершения трека, с.
dur | Длительность жизни (tEnd − t0), с.
visibleSec | От рождения до последнего привязанного блоба, с.
sinceLastBlobSec | От последнего блоба до конца трека (хвост пропуска), с.
frames | Число кадров жизни трека, учтённых CORE (tr.frames).
nBlobs | Число блобов, привязанных к треку.
bornZone | Зона кадра при рождении: FAR (дальняя), MID, NEAR (ближняя) — по доле пройденной калибровочной зоны.
confirmed | 1 — трек двигался и прожил confirmFrames кадров (подтверждён как движущийся объект).
tConfirm | Секунд от рождения до подтверждения.
moved | 1 — CORE признал трек сдвинувшимся (tr.moved).
shown | 1 — по треку когда-либо показывалось число (в любой момент жизни).

tShow | Секунд от рождения до первого показа числа.

early | 1 — первое число показано РАННИМ способом (по воротам, mode gate).

kmhLive | Последнее «живое» значение tr.kmh на момент конца, км/ч.

kmhLiveMax | Максимальное живое значение за жизнь, км/ч.

#eventTypes
stab_state | Смена состояния стабилизатора кадра (ok, init, coast, lost, off). Без трека. Показывает, когда измерения шли без стабилизации.
birth | Рождение трека: первый блоб, не привязанный ни к одному треку. Записывает место рождения (зона, рамка детектора под блобом).
confirm | Трек подтверждён: двигался и набрал confirmFrames кадров (условие «подтверждён» воронки).
show | Трек показал число скорости. mode=gate — ранняя скорость по воротам (Tracker._early), mode=wls — скорость по регрессии. Фиксирует момент и качество первого показа.
miss_start | Начало пропуска: у трека в кадре нет привязанного блоба. Записывает прогноз положения и ближайшую рамку детектора (nd).
miss_end | Конец пропуска: блоб снова привязан. via говорит, как именно (normal / recover / hold), gateRej — почему блоб не привязывался во время пропуска.
miss_open_at_end | Пропуск не закончился до конца жизни трека (трек убит или завершён во время пропуска). Поля как у miss_end, via=open.
lost | Трек, у которого число уже было показано, слишком долго не получал блоб (why=miss или occluded) и переведён CORE в список «потерянных» на reviveSec: найдётся подходящий блоб — трек возродится (revive), нет — завершится (limboExp). Записывает, была ли под прогнозом рамка детектора (vdAtPred), и ближайшую рамку (nd).
revive | Потерянный трек возобновлён с тем же ID: появился блоб, согласующийся с метрическим прогнозом траектории (по s и по x), не позже reviveSec после потери.
recover | Живой трек с пропуском в 1 и более кадров получил блоб той же полосы, согласующийся с метрическим прогнозом (по s) либо накрывающий прогноз (info.ov=1): CORE принял его как продолжение. Принятому только по перекрытию кромке не верят, и точка в регрессию не идёт.
id_switch | CORE зафиксировал смену ID: новый трек родился там, где ожидалась недавно потерянная и не возрождённая машина (не дальше 4 м по s от экстраполяции её траектории и не дальше 2,5 ширин по x, не позже 1,5 с после окончания лимба). replaces — какой закончившийся трек заменён (подбор по тому же критерию, зеркало CORE).
dup_kill | Дубль убит: трек признан дублем другого (общий блоб или осколки под одной рамкой детектора, via=det_box). keptId — какой трек оставлен.
xlane_blocked | Блоб соседней полосы не привязан к треку: он лежит вне полосы трека (перекрытие с полосой трека меньше доли xlaneMinOv его ширины) и не прошёл исключение «объединение с осколками» (XLANE_BLOCKED). Журнал хранит только первые 3 такие записи на трек; полное число — поле nXb в строке трека.
frag_suppressed | Непривязанный блоб не стал новым треком (FRAG_SUPPRESSED): он перекрывается по x с блобом трека той же полосы, получившего блоб в этом же кадре, и либо выше его кромки, либо меньше 0,6 его площади — считается осколком той же машины.
lane_switch | Трек сменил полосу (from → to); restarted=1 — набор точек начат заново.
end | Трек закончен: итог (res/cause), чем закончен (endBy), до какой стадии дошёл (stage) и где потерян (stageLost), причина HIGH_RMS и класс «ранняя → итог», если есть.
cluster_owner | Кластер: блобы соседних полос, соприкасающиеся через границу полосы (машина на границе). Оставлен «владелец» — блоб с самой нижней кромкой (ближе к камере; при равенстве в пределах ownerTol — самый крупный) среди блобов с площадью не меньше max(minAreaPx, ownerFrac × максимум); остальные блобы кластера отброшены, их площадь запомнена в owner-площади (exA). Без трека.
blob_merge_gap | Два блоба склеены по зазору ≤ mergeGapPx (BLOB_MERGED, склейка по расстоянию). Без трека.
blob_merge_det | Два блоба склеены потому, что их накрывает одна рамка детектора (BLOB_MERGED по детектору). Без трека.
area_jump | Скачок площади блоба трека между соседними кадрами (AREA_JUMP; q = площадь/предыдущая).
x_jump | Скачок координаты x блоба трека (X_JUMP).
size_jump | Скачок ширины/высоты блоба относительно предыдущего наблюдения больше порога xcfg.sizeJump.
time_gap | Интервал между соседними наблюдениями трека больше xcfg.gapSec (в наблюдениях трека, не в кадрах видео).
blob_merged_start | У блоба трека появился признак склейки (mg > 0), которого не было в предыдущем наблюдении.
blob_merged_end | Признак склейки блоба трека исчез.
owner_drop_start | Начало состояния «часть блоба отброшена как чужая» (exA > 0): владелец кластера отбросил часть площади.
det_box_lost | Рамка детектора, покрывавшая блоб трека в прошлом наблюдении, больше блоб не покрывает (рамка пропала, сместилась или детектор не вызывался).
dv_change | Соседние наблюдения трека лежат в разных цепочках детектора: признак склейки двух машин или смены ID (гипотеза).
cls_change | Соседние наблюдения трека покрыты рамками разных классов детектора (car ↔ truck и т.д.).
finish_attempt | Одна попытка итоговой оценки (вызов Tracker._finishCore по сегменту точек). У одного трека бывает несколько. Подробности — таблица attempts.
redetect | Новая цепочка детектора похожа на продолжение оборвавшейся 1,2–4 с назад (согласие по s и скорости). Цепочки НЕ объединяются: это только связь для оценки числа машин.

#pointAttribution
КАК ЧИТАТЬ | Раздел отвечает на вопрос «какие измерения создают большие невязки». Для каждого трека с восемью и более точками берётся устойчивая прямая C (метод Тейла–Сена по ВСЕМ точкам трека, включая отброшенные онлайн); z = |невязка точки от C| / σ точки. Точки раскладываются по классам треков и по контекстам. Сравнивайте класс HIGH_RMS с PASS1 по одному и тому же контексту: контекст объясняет большие невязки, если доля точек с z > 3 при нём заметно выше, чем без него, и контекст не присутствует на всех точках подряд.
tracks | Сколько треков вошло в каждый класс (JSON: pointAttribution.tracks).
bins | Границы интервалов z в гистограмме h: ≤1, ≤2, ≤3, ≤5, ≤10, >10.
table | JSON: pointAttribution.table[класс][контекст] = {n, h, z2}.
table.n | Сколько точек имеют этот контекст.
table.h | Шесть чисел: сколько из них попало в каждый интервал z (см. bins). Доля z > 3 = сумма трёх последних / n.
table.z2 | Сумма z² этих точек (z² каждой точки ограничено 10000). Вклад контекста в общую сумму = z2 / z2 контекста ALL.
класс PASS1 | Треки с проверенным итогом T1.
класс PASS2 | Треки только с предварительным итогом T2.
класс HIGH_RMS | Треки, закончившиеся отказом HIGH_RMS, HIGH_REL_ERR, RMS_AND_REL или UNVERIFIED.
класс OTHER | Остальные треки (дубли, мало точек, не подтверждены и т.д.), у которых хватило точек.
ALL | Все точки класса.
noFlag | Точки без единого флага контекста блоба (из списка флагов точки ниже).

КАК ЧИТАТЬ | Раздел описывает значения полей-перечислений (коды причин, стадий, классов). Формат ключа: поле.значение. Коды без префикса REJECT_ берутся из CORE v4 как есть; поля с пометкой «гипотеза» — результат классификатора диагностики, а не измерение.
